# MahitiBazaar Web Login — Content Update Guide

**Audience:** Content Team
**Product:** MahitiBazaar Web Login
**Date:** 27 October 2026
**Sources:** `docs/MBWebLogin_PRDv1.md` and `docs/26-Mahitibazaar-Multi-Services-Category-Title.md`
**Companion:** `docs/Web_Login_Asset_Creation_Guide.md`

Use this checklist to create and update catalogue content. Service titles are copied from the Multi-Services document and are the Title field. Categories follow the Web Login PRD.

The source albums are listed on each row so a title can be traced. They are not the Web Login category.

## Work order

Later steps depend on earlier ones.

1. Admin decides every row in **Uncertain services**. Leave those records unpublished until that decision.
2. Admin confirms each **Proposed** category name. Drafts can be prepared with the name in this guide. Publish after the name is accepted.
3. Create the states the catalogue will use. Maharashtra is the home state for state schemes and state licences. A national service (Aadhaar, PAN, GST, passport, income tax, voter card, EPFO) still needs a State value, because the PRD shows content by state and by the states on the Center Owner’s plan.
4. Create the categories below, each on the matching module (e-Mahiti or e-Seva).
5. Add every new category to the subscription plans that should see it. A published record stays hidden from a Center Owner whose plan does not allow that state and category.
6. Create tags. The PRD uses tags for search, filtering, grouping, and recommendations. Suggested tags are on each section.
7. Take card and poster files from the asset guide. Upload subcategory cards to the image library.
8. Create each service as **Draft**, with the asset id stored in the working notes.
9. Attach the poster, the library image, links, and supportive documents.
10. Publish when the section checklist and the row notes are done.

Help Center articles, page banners, and general messages are separate from this catalogue. They are not part of these service rows.

## How a service was placed

| Module | PRD meaning | Dates |
| --- | --- | --- |
| e-Mahiti | Time-bound information: jobs, admissions, scholarships, schemes, exams | Start Date and End Date. The record becomes Expired when the current UTC date is after the End Date. |
| e-Seva | A standing service with no end date | Start Date only. The PRD gives e-Seva no End Date. |
| Uncertain | More than one PRD module fits, or the row fits e-Link | No publish decision yet. |

e-Link is the PRD module for results, admit cards, exam forms, and official websites. It stores links, a display window, state, and category. It has no posters, advertisements, or document folders. This checklist does not move a row there until Admin says so.

A **PRD category** is a category example in the PRD. A **PRD example** is Income Tax or MSME: named as an e-Seva example, not in the category list. A **Proposed** subcategory groups a purpose the PRD does not name.

## Mandatory fields

### Every e-Mahiti row

- [ ] Title, exactly as written in the row.
- [ ] Short description in Marathi. The PRD asks for service information in the local language and shows Marathi on the card (`तपशील पहा`). Write two or three lines that stand alone on the detailed card, then the rest of the rich text.
- [ ] Start Date and End Date from the official notice. Enter an end date when the notice gives one. Leave the record in Draft while the end date is unknown.
- [ ] Display Start Date and Display End Date. Use the same window as Start and End unless the item should appear for a different period. Display End is on or after Display Start.
- [ ] State.
- [ ] Category for this section.
- [ ] At least one official link, with a label and a URL, when the citizen action is online.
- [ ] Poster file from the asset guide, so poster-thumbnail layout has an image.
- [ ] Library image: the card file from the asset guide. An empty library image keeps the poster thumbnail or the default image.
- [ ] Tags from the section suggestion, plus any official short name.
- [ ] Supportive documents for the papers the center collects, each with a Display Name when the file name would be unclear. Posters do not use a Display Name.
- [ ] Status moves from Draft to Published only after this list and the row note are done.

The detailed card shows one date line. A past date, or a date within 7 days, is red. A later deadline or a future start is green. A start date with no end date stays neutral.

### Every e-Seva row

- [ ] Title, exactly as written in the row.
- [ ] Short description in Marathi, with two or three lines that stand alone on the card.
- [ ] Start Date. Leave End Date empty. e-Seva has no expiry date in the PRD.
- [ ] Display Start Date.
- [ ] State. For a national service, confirm with Admin whether Maharashtra is the only state record.
- [ ] Category for this section.
- [ ] At least one official link, with a label and a URL.
- [ ] Poster file and library image from the asset guide.
- [ ] Tags, supportive documents, and Display Names, on the same rules as e-Mahiti.
- [ ] Publish from Draft only after this list and the row note are done.

### Every uncertain row

- [ ] Record Admin’s module and category decision on the row.
- [ ] After the decision, follow the e-Mahiti checklist, the e-Seva checklist, or the e-Link path below.
- [ ] Leave the record in Draft until that decision.

e-Link path, if Admin chooses it: Title, short description, one or more links (label, URL, and display order), Display Start Date, Display End Date on or after the start, State, Category, tags, and Published status. No poster, advertisement, or document folder.

Advertisements are optional on e-Mahiti and e-Seva. Add one only when the center is meant to download a ready creative. Give it a Display Name.
